# Discord Manager 2.0 Base

방송인용 Discord 서버를 자동 구성하고 관리하기 위한 중립형 베이스 봇입니다.

기존 특정 방송인용 구현에서 서버 구조와 기능은 유지하되, 역할명·채널명·안내 문구·닉네임 제출 문구처럼 방송인별로 달라지는 요소를 `config.py`로 분리했습니다. 새 방송인용으로 사용할 때는 가급적 `main.py`를 직접 수정하지 말고 `config.py`의 값만 바꾸는 것을 권장합니다.

## 기본 역할

- `Owner`: 서버 소유자용 관리자 역할
- `Manager`: 서버 관리자
- `Streamer`: 타 방송인/합방 참여자
- `Viewer`: 일반 시청자. 신규 일반 멤버에게 자동 부여됩니다.

`Owner`와 `Manager`는 Administrator 권한을 갖습니다. `Streamer`는 합방 관련 채널을 볼 수 있으며, `Viewer`는 일반 시청자용 권한을 가집니다.

## 주요 기능

### `/setup check`

현재 서버가 `config.py`와 코드에 정의된 구조와 일치하는지 확인합니다. 서버를 수정하지 않습니다.

### `/setup sync`

기존 서버를 최대한 유지하면서 역할, 분류, 채널, 권한, 채널 순서, 닉네임 제출 안내 등을 현재 설계에 맞춥니다.

멤버 개인에게 직접 지정한 채널 권한과 봇이 관리하지 않는 추가 역할의 권한 덮어쓰기는 보존합니다.

### `/setup reset`

서버 구조를 대대적으로 삭제한 뒤 다시 만듭니다. `관리기록` 채널과 `Owner / Manager / Streamer / Viewer` 역할 및 해당 역할의 기존 멤버 배정은 보존합니다.

파괴적인 작업이므로 `confirm`에 정확히 `RESET`을 입력해야 실행됩니다.

### `/방송공지`

`방송공지` 채널에 공지를 전송합니다.

### 닉네임 비공개 제출

`닉네임 제출` 채널은 일반 멤버에게 읽기 전용입니다. 고정된 `닉네임 제출` 버튼 또는 `/닉네임` 명령으로 모달을 열어 제출합니다.

- `닉네임_DB`: 서버 닉네임 / 게임 닉네임 / 게임명만 기록
- `관리기록`: Discord 사용자명과 User ID, 서버 닉네임, 게임 닉네임, 게임명, UTC+9 제출 시각을 상세 기록
- 제출 내용은 공개 채널에 게시하지 않음
- 안내 메시지는 자동으로 생성·갱신·고정(pin)

## 방송인별 커스터마이즈

`config.py`에서 아래 항목을 바꿀 수 있습니다.

- 역할명
- 분류명
- 채널명
- 닉네임 제출 채널 topic
- 닉네임 안내문
- 버튼 이름과 custom ID
- 모달 입력란 문구
- 제출 완료 응답

예를 들어 시청자 역할을 특정 팬덤명으로 바꾸려면:

```python
ROLE_NAMES = {
    "owner": "Owner",
    "manager": "Manager",
    "streamer": "Streamer",
    "viewer": "팬덤명",
}
```

채널명도 같은 방식으로 수정할 수 있습니다. 이름을 바꾼 뒤 이미 운영 중인 서버에 적용할 경우 기존 채널을 자동으로 이름 변경하는 마이그레이션 기능은 기본 제공하지 않으므로, 신규 서버에서 사용하거나 별도 마이그레이션 규칙을 추가하는 것을 권장합니다.

## 설치

Python 3.11 이상을 권장합니다.

```bash
python -m venv .venv
source .venv/bin/activate  # Windows: .venv\Scripts\activate
pip install -r requirements.txt
```

`.env.example`을 참고해 `.env`를 만듭니다.

```env
DISCORD_TOKEN=your_token_here
```

Discord Developer Portal에서 봇에 `SERVER MEMBERS INTENT`를 활성화해야 합니다. 신규 멤버의 `Viewer` 자동 부여와 입장·퇴장·역할 변경 기록에 사용합니다.

실행:

```bash
python main.py
```

## 권장 봇 권한

서버를 자동 구성하려면 봇에 `Administrator` 권한을 주는 것을 전제로 합니다. 역할을 관리하려면 봇 역할이 관리 대상 역할보다 위에 있어야 합니다.

## 기본 설계 원칙

서버의 역할·채널·권한 구조는 봇이 소유하는 선언형 설정으로 취급합니다. 운영 중 수동으로 구조를 바꾸면 `/setup check`에서 차이로 표시되고 `/setup sync` 실행 시 설계값으로 되돌아갈 수 있습니다.

방송인별 표현과 명칭은 `config.py`, 구조 및 권한 동작은 `main.py`에 두어 서로 섞이지 않게 유지하는 것이 이 저장소의 기본 방향입니다.
